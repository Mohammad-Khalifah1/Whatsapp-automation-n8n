WhatsApp Support Routing

How a customer's message arrives, how it is shared out across the team, and where it is tracked.

The idea, in two lines

A customer messages your WhatsApp business number. The system recognises them, opens a conversation, and hands it automatically to whoever has the fewest open conversations. Everything appears in a colour-coded Google Sheet where a manager can see at a glance who is waiting, and for how long.

The journey of one message

1

The customer sends a message

From ordinary WhatsApp to the company number. They install nothing.

2

Meta sends a signed notification

It calls our URL immediately, attaching a cryptographic signature that proves the request really came from Meta.

3

Verify the signature, then acknowledge at once

Anything unsigned is rejected. We then answer Meta in under a tenth of a second — before any slow work, so it does not retry and deliver the message twice.

4

Read the message, and refuse duplicates

Name, number, text and timestamp are extracted. If the same message arrives twice, the second is ignored — no duplicate conversation and no double assignment.

5

New conversation, or an existing one?

If the customer already has one open, we continue it and keep it with the same agent. If not, a new one is opened.

6

Choose the agent

From the agents who are active, available and not at capacity, we take the one with the fewest open conversations. Ties break by oldest assignment, then by a fixed order — so the outcome can always be explained.

7

It all appears in the sheet

One row per conversation, coloured by state, with a direct link to the customer's chat. The request type is classified against a Categories tab you edit yourself — add a product line by adding a row.

If no agent is free — the conversation is never lost. It is recorded as WAITING_FOR_AGENT with the reason stated, and the system retries the assignment every five minutes.

Any column can be sorted: state, agent, date, customer name. There is also a Dashboard tab with six live figures and four charts — message volume over fourteen days, the mix of states, the load on each agent, and what customers are asking for. The most useful view: status = UNANSWERED, oldest first.

Three ways to reply — all of them recorded

The WhatsApp Business app

instant

The agent replies in an app they already know, with notifications. Requires Coexistence to be enabled.

Typing in the sheet

≤ 1 minute

Type into the reply_text column; it is sent automatically and the cell is cleared. No training at all.

Through the API

instant

For the future agent inbox, or for automation.

The one exception: if an agent replies from their personal WhatsApp, the system cannot see it — the message never passed through the company number. No system anywhere could track it.

What stops things going wrong

RiskWhat prevents it
Forged messages from an unknown sourceMeta's cryptographic signature is verified — anything unsigned is rejected
The same message arriving twiceA deduplication key on the message id — the second is ignored
Two customers assigned to one agent at the same instantAssignments run one after another
A corrupt row in the agents tableThat one agent is excluded — routing continues
An unrecognised value in the "available" fieldTreated as unavailable — always the safer reading
A message type we have never seenRecorded and marked unsupported, rather than breaking the system
The sheet growing unmanageableNightly archiving of old closed conversations
